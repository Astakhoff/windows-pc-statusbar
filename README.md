# Windows PC Status Bar

PCStatusBar 1.5 — панель состояния Windows 11: системные показатели справа и цветная лента тегов Codex / Claude слева. Есть отдельная AppBar и адаптивное наложение внутри taskbar. C# / WinForms / .NET 10 LTS, без веб-сервера и запросов к модели.

## Установка и запуск

Требуются Windows 11 и .NET 10 SDK для сборки. Установленная self-contained сборка не требует SDK или отдельно установленного .NET Runtime.

Откройте PowerShell в каталоге репозитория:

```powershell
.\build.ps1
.\install.ps1 -SkipBuild
```

Или выполните `.\install.ps1`, чтобы сначала собрать приложение. Скрипты не меняют execution policy и не требуют повышения прав. Для ARM64: `.\build.ps1 -Runtime win-arm64`.

Приложение устанавливается в `%LOCALAPPDATA%\Programs\PCStatusBar`, запускается и получает ярлыки в меню «Пуск» и автозапуске текущего пользователя. Повторная установка сохраняет настройки, текущее включённое или выключенное состояние автозапуска и заменяет только файлы предыдущей установки, перечисленные в её манифесте.

## Размещение и управление

Доступны два режима. Обычная AppBar **над штатной панелью задач**, высотой 38 логических пикселей по умолчанию, резервирует полосу по ширине выбранного монитора. Альтернативный режим — **наложение внутри горизонтального taskbar выбранного монитора**; отдельное резервирование AppBar освобождается.

Режим выбирается флажком «Наложение внутри taskbar». По умолчанию включено «Автосжатие по размеру и занятым областям taskbar»: панель проверяет прямоугольник taskbar каждую секунду, а геометрию кнопок приложений и трея читает в фоне раз в три секунды. Отступы масштабируются пропорционально ширине относительно базовой ширины, которая при значении 0 запоминается автоматически. Фактически занятые участки дополнительно защищены от наложения с небольшим отступом. При изменении размеров, монитора или DPI позиция пересчитывается. Если свободного участка нет, ширина становится нулевой; управление остаётся в трее. При отсутствии достоверного измерения панель ждёт его, а устаревший более чем на 15 секунд снимок не используется.

Начальные отступы — 560 слева и 240 справа. При базовой ширине 3440 и DPI 96 это даёт x=560, y=1397, 2640×38 между текущими кнопками приложений и треем. Отключение автосжатия возвращает фиксированные отступы в логических пикселях. Это отдельное окно поверх taskbar без встраивания или резервирования места в Explorer; изменения кнопок учитываются с задержкой опроса. Настройки сохраняются для автозапуска.

Ширина каждого блока рассчитывается по текущему тексту. При недостатке места сначала включаются компактные подписи: RAM в процентах, диски в GiB, укороченные лидеры. Затем блоки скрываются в порядке: график, лидеры, GPU, очередь, D:, C:, RAM, CPU. Кнопка «…» открывает снимок всех значений; тот же список доступен в меню «Все показатели…». Подсказки сохраняют полный текст. При расширении области блоки возвращаются автоматически. Лента занимает оставшееся место слева.

Порядок слева направо: «Лидеры» → «Очередь» → CPU → график → RAM → «C: свободно» → «D: свободно» → GPU (если включён). C: и D: — отдельные адаптивные блоки с собственными значениями и цветом, без дополнительного тире между ними. Группа выровнена справа: изменение ширины крайнего левого блока «Лидеры» не сдвигает остальные блоки.

**Шестерёнка справа** открывает список с галочками для каждого из восьми блоков и ленты Codex / Claude. Снятие галочки сразу скрывает элемент и освобождает место; повторное нажатие возвращает его. Выбор сохраняется автоматически и применяется после перезапуска. Изначально все элементы включены, существующая настройка GPU сохраняется. Шестерёнка остаётся доступной, даже если выключены все элементы. Тот же список доступен в меню трея «Видимость блоков…». Автосжатие скрывает только включённые элементы и не меняет галочки; окно «Все показатели…» по-прежнему показывает полный снимок.

### Бегущая строка лимитов

Свободную область слева занимает плавная лента цветных тегов: **[Codex] [week] [%] [время] → [Claude] [week] [%] [время] → [Claude] [5 часов] [None или %]**. У названий сервисов разные акцентные цвета, у периода и остатка собственные фоны. При остатке 25% и менее значение выделено янтарным, при 10% и менее — красным. Недоступные данные показаны серым тегом **None**. Пятичасовая позиция Codex скрыта в ленте и подробностях. Для каждого доступного окна показаны оставшийся процент и время до сброса (дни / часы либо часы / минуты). Наведение приостанавливает движение; нажатие открывает значения, источники, точные даты сброса и причины отсутствия данных. Окно доступно также через меню «Лимиты Codex и Claude».

Источники:

- **Codex**: установленный desktop CLI, локальный stdio-интерфейс `app-server`, документированный запрос `account/rateLimits/read`. Используется уже выполненный вход текущего пользователя. Панель не читает и не копирует токены, не запускает чаты и не расходует лимит на ответы модели. Путь CLI определяется по установке в `%LOCALAPPDATA%\OpenAI\Codex\bin`. Короткий вспомогательный процесс запускается раз в минуту с тайм-аутом 20 секунд и закрывается после чтения.
- **Claude**: только чтение индикатора `Usage:` из дерева доступности установленного приложения Windows. Панель не нажимает кнопки, не меняет фокус, не открывает настройки и не читает переписку или файлы авторизации. Должен быть доступен индикатор во вкладке Code. При закрытом приложении или отсутствии индикатора показывается отсутствие данных. Значения повторяют состояние индикатора; панель не заставляет Claude обновить его на сервере. Время вида `Fri 8:00 PM` трактуется в локальном часовом поясе Windows; неподдерживаемый формат оставляет время недоступным.

Опрос выполняется в фоне раз в минуту и по кнопке «Обновить». Работа системных показателей не ждёт ответа сервиса. У зависшего провайдера доступности остаётся максимум один запрос; новые не накапливаются. Данные старше трёх минут становятся **None** в ленте, а причина указана в подробностях; после даты сброса старый процент не выдаётся за новый лимит. Если источник не возвращает окно, лента показывает **None**; это не означает 100% или отсутствие ограничений. Проценты вычисляются как `100 − использовано`, а не как число токенов.

На проверенной конфигурации Codex возвращал только недельное окно, а индикатор Claude показывал только недельный общий лимит. Пятичасовая позиция Claude показывает None до появления данных; позиция Codex скрыта по выбранному оформлению. Файл истории лимитов Claude не используется: он может быть устаревшим и не содержит всех дат сброса.

Для нового сервиса добавляется реализация `IQuotaProvider`, возвращающая нормализованные окна `QuotaSnapshot`; отображение и прокрутка общие для всех провайдеров.

- Правая кнопка по панели или значку трея — настройки, показать/скрыть, автозапуск, Диспетчер задач, выход.
- Двойной щелчок по показателю или значку трея открывает настройки.
- Нажатие на блок «Лидеры» открывает список отдельных процессов с PID и долей CPU; доступен также пункт меню «Потребители CPU».
- Повторный обычный запуск открывает настройки существующего экземпляра.
- Кнопка закрепления ярлыка находится в настройках. Проверяются desktop API, ограничения LAF, разрешение Windows и существующее закрепление. Запрос вызывается только по нажатию пользователя и требует подтверждения Windows. При недоступном API используйте штатное закрепление PCStatusBar через меню «Пуск».

Живая панель, значок трея и закреплённый ярлык — отдельные элементы. Закрепление ярлыка не требуется для работы панели.

## Показатели и цвета

| Показатель | Жёлтый | Красный | Ухудшение | Восстановление |
|---|---:|---:|---|---|
| CPU | ≥70% | ≥90% | 5 с непрерывно | 5 с, запас 5 п.п. |
| RAM | ≥80% | ≥90% | 3 с непрерывно | 5 с, запас 3 п.п. |
| C: / D: свободно | ≤15% | ≤5% | при чтении | запас 2 п.п. |

Пороги и интервалы меняются в интерфейсе. Это уровни внимания, а не диагноз неисправности. Серый означает отсутствие достоверных свежих данных. Для температуры серое **число** означает, что данные есть, но пороги не настроены; «—» означает отсутствие данных.

CPU и RAM опрашиваются раз в секунду, C: и D: раз в 10 секунд, GPU раз в 2 секунды. Для дисков используется общий набор настраиваемых порогов, но состояние, чтение и доступность каждого блока независимы. При недоступности D: только его блок показывает «—». Подсказки объясняют источник, единицы и текущий цвет. GiB = 1024³ байт.

### Очередь, потребители и график CPU

- **Очередь** — мгновенное число готовых потоков, ожидающих процессор, из `System\Processor Queue Length` через PDH. Обновляется раз в 3 секунды; это число потоков, а не агентов. В подсказке указано число логических CPU. Универсальный цветовой порог не назначается.
- **Лидеры** — три программы с наибольшим суммарным CPU по доступным процессам, сгруппированные по имени без учёта регистра. Доли рассчитаны по разности CPU time за интервал около 3 секунд и нормализованы на всю мощность компьютера. Например, несколько `python` складываются в одну группу. Совпадение имени не означает принадлежность одному агенту. Нажатие открывает до 100 отдельных процессов, отсортированных по CPU, с PID и процентом. Недоступные и завершившиеся во время чтения процессы пропускаются; их число есть в подсказке и списке. Первый опрос задаёт базу. Командные строки и пути процессов не считываются.
- **График CPU** — компактная линия без текстовой подписи. Скользящее окно по монотонному времени: слева минута назад, справа сейчас, вертикальная шкала 0–100%. Оно заполняется реальными отсчётами после запуска; пропуски и длительные разрывы не соединяются линией. В подсказке — период 60 секунд, среднее отсчётов и максимум. Последняя минута хранится только в памяти и сбрасывается при перезапуске, возобновлении после сна или применении настроек.

Если счётчик очереди недоступен, показывается «—». Устаревшие сведения о потребителях убираются через 9 секунд. Сбор данных выполняется в фоне; PowerShell и WMI-процессы при опросе не запускаются.

GPU core читается через NVML из установленного драйвера NVIDIA в System32, устройство #0. Дополнительные драйверы не устанавливаются. CPU Package, AMD/Intel GPU и дополнительные видеокарты этим температурным провайдером не поддерживаются. Пользовательские пороги GPU можно задать в настройках; по умолчанию они пусты.

CPU через GetSystemTimes поддерживает одну processor group (до 64 логических процессоров); при нескольких группах показывает явную недоступность вместо частичной «общей» нагрузки. Свободное место читается отдельно для C: и D: с учётом квоты текущего пользователя.

## Автозапуск и удаление

Отключить автозапуск можно в настройках или меню трея. Это запуск после входа текущего пользователя; служба и системная задача не создаются.

```powershell
.\uninstall.ps1
# Дополнительно удалить настройки и локальную диагностику:
.\uninstall.ps1 -RemoveSettings
```

Копия `uninstall.ps1` также находится в папке установленного приложения. По умолчанию настройки сохраняются в `%LOCALAPPDATA%\PCStatusBar\settings.json`. Запись атомарная; повреждённые настройки заменяются рабочими значениями по умолчанию. Логи ограничены по размеру и повторениям; постоянная история метрик на диске не ведётся.

## Проверки

```powershell
dotnet run --project tests/PCStatusBar.Tests.csproj -c Release
# Для уже установленной и работающей панели; временно скрывает и перезапускает её:
.\smoke-test.ps1
# Временно сжимает только панель, затем восстанавливает ширину:
.\responsive-smoke-test.ps1
```

71 проверка расчётов, цветовых переходов, CPU процессов, минутного окна, тегов лимитов и адаптивной геометрии; Release-сборка, 20 проверок установленной панели и 10 проверок сжатия до 1100 / 650 / 150 пикселей. Проверены отсутствие выхода блоков за границы, компактные подписи, скрытие блоков, доступность «…», возврат ширины и сохранение настроек. В расчётных тестах проверены уменьшение разрешения, рост занятой области, отрицательные координаты и отсутствие свободного места. Реальное переключение разрешения, второго монитора и DPI для версии 1.4 не выполнялось. Ранее проверено переключение AppBar / taskbar overlay. GitHub Actions собирает self-contained win-x64 и сохраняет артефакт сборки.

Проверены реальные CPU/RAM/C:, температура GPU, вид панели при DPI 96, настройки, ярлыки, повторная установка, один экземпляр, резервирование, скрытие/показ, штатный выход и обычное развёрнутое окно. Не проверены вход после перезагрузки, перезапуск Explorer, сон, переключение DPI, отключение монитора, fullscreen и ARM64. Подтверждение закрепления оставлено пользователю.

В отдельном 20-секундном замере версии 1.1 после прогрева: около 0,32% общей мощности CPU, working set 107 MiB, private bytes 51 MiB. Это измерение на проверенной конфигурации с закрытым окном процессов, а не гарантия для всех компьютеров. Для версии 1.0 проверено также удаление установленных файлов и ярлыков с сохранением настроек и последующая установка.

Для версии 1.2 с движущейся лентой: около 0,67% общей мощности CPU основного процесса, working set 121 MiB, private bytes 54 MiB за 20 секунд. Короткий процесс Codex для чтения лимитов в этот замер основного процесса не входит.

Для версии 1.3 с цветными тегами в фиксированном taskbar overlay: около 0,89% общей мощности CPU основного процесса, working set 117 MiB, private bytes 51 MiB за 20 секунд на проверенном компьютере.

Для диагностики по запросу:

```powershell
& "$env:LOCALAPPDATA\Programs\PCStatusBar\PCStatusBar.exe" --diagnostics
```

Снимок записывается только по запросу в `%LOCALAPPDATA%\PCStatusBar\diagnostics.local.json`, без истории. Доступны также `--show`, `--hide`, `--exit`. Временные `--inspect` / `--end-inspect` делают окно доступным инструментам GUI-проверки и возвращают обычный режим. `--check-maximized` кратко открывает тестовое окно и записывает его границы. Эти режимы не подменяют реальные показатели.

`--taskbar-overlay` и `--appbar` переключают работающий экземпляр и сохраняют режим. `--taskbar-regions` создаёт расширенный локальный снимок геометрии элементов taskbar в `taskbar.local.json`; автоматическое позиционирование использует отдельный фоновый замер прямоугольников кнопок без чтения их названий. `--preview-width 650` временно ограничивает ширину окна для проверки сжатия, `--preview-width 0` возвращает обычную ширину. Ограничение не сохраняется, не меняет разрешение Windows и не подменяет реальные метрики.
