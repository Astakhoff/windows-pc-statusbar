# Реализация

`Metrics` читает общие системные времена CPU, физическую память и доступное текущему пользователю место на C: и D: через Win32. Каждый диск опрашивается отдельно и имеет собственный StatusEvaluator; общий набор порогов не объединяет состояния блоков. Первый отсчёт CPU задаёт базу. Ошибки не заменяются нулями. Провайдеры изолированы, выполняются последовательно в фоновом задании без накопления параллельных опросов.

`StatusEvaluator` получает монотонное время, ведёт независимые интервалы жёлтого и красного превышения, допускает прямые переходы, использует запас и выдержку восстановления. Разрывы и отсутствующие данные сбрасывают непрерывность. Интерфейс проверяет свежесть: max(5 секунд, 3 × интервал).

`CpuInsightsProvider` держит один PDH query для языково-независимого `System\Processor Queue Length`, читает его раз в 3 секунды с `PDH_FMT_LONG | PDH_FMT_NOCAP100` и закрывает при выходе. Перечисление процессов выполняется тем же фоновым опросом без пересечения запросов. Снимки CPU time сопоставляются по PID и времени запуска, поэтому повторно использованный PID не наследует чужой CPU. Делитель — реальное время интервала и число активных логических процессоров всех групп. Каждый объект Process освобождается; ошибки прав и завершение процесса изолированы. Данные защищённых процессов могут отсутствовать, поэтому лидеры относятся к доступной выборке.

`ProcessAccounting` вычисляет доли и группирует по имени программы. `ConsumersForm` показывает до 100 отдельных процессов и обновляется теми же измерениями без дополнительного опроса. `CpuHistory` ограничивает выборку последними 60 секундами и максимум 600 точками; штатно это около 60 отсчётов. `CpuGraph` рисует линии только между свежими достоверными соседями, не растягивая короткую историю на всю минуту. История не записывается на диск. Диагностика по явному запросу может включать текущий снимок процессов и историю; она остаётся локальной.

`BarForm` регистрирует AppBar через ABM_NEW / ABM_QUERYPOS / ABM_SETPOS и использует возвращённые координаты. ABM_REMOVE освобождает полосу при скрытии и закрытии. Обработаны уведомления позиции, активации, изменения окна, DPI, экрана, fullscreen, восстановления Explorer и питания. При отсутствии выбранного монитора используется основной; координаты могут быть отрицательными. Для предотвращения рекурсивного позиционирования используются флаги и очередь UI.

В режиме `TaskbarOverlay` регистрация AppBar удаляется. `TaskbarOverlay.FindForMonitor` находит Shell_TrayWnd / Shell_SecondaryTrayWnd для выбранного монитора через EnumWindows и GetWindowRect. Раз в секунду проверяются размер и DPI, раз в три секунды в фоне читаются только прямоугольники кнопок UI Automation. Названия кнопок для позиционирования не нужны. `OccupiedInsets` выделяет правую группу трея и край кнопок приложений; неполное дерево отвергается. Одновременно выполняется максимум один UIA-запрос. Последний успешный замер хранится до 15 секунд, при его отсутствии окно получает нулевую ширину до восстановления источника.

`OverlayGeometry.Adaptive` масштабирует отступы относительно запомненной базовой ширины taskbar и ограничивает результат фактическими занятыми областями с защитным отступом. Обрабатываются отрицательные координаты и нулевая свободная ширина. Если автосжатие выключено, `Calculate` оставляет фиксированные отступы с учётом DPI. SetWindowPos вызывается при изменении границ. Окно не становится дочерним Explorer, код не внедряется, внутренняя разметка taskbar не меняется; задержка измерения означает, что это не мгновенное резервирование места.

`ResponsiveLayout` рассчитывает полные ширины, затем компактные, затем скрывает блоки по приоритету до вмещения. Он оставляет область для ленты и добавляет «…» для снимка всех показателей. Расчёт не зависит от WinForms и проверяется на всех целых ширинах 0–3000. `BarForm` применяет план за один проход с приостановленной раскладкой, сохраняя полные сведения в подсказках. `--preview-width` ограничивает только текущий viewport без записи настроек.

Без захвата фокуса поддерживается верхний z-order. Для borderless fullscreen используется проверка переднего окна по стилю и покрытию монитора; реальные игры и все разновидности fullscreen требуют отдельной проверки. В AppBar-режиме остаются системные fullscreen-уведомления.

`Temperature` использует только уже установленную NVML из System32. GPU #0, sensor GPU core. Нулевые, ошибочные и неправдоподобные значения отвергаются. Пороги не назначаются автоматически; пользователь может ввести собственные в °C. CPU Package не подменяется ACPI-зоной. После отсутствия DLL приложение продолжает работу без этого блока.

`IQuotaProvider` отделяет источники от модели `QuotaSnapshot`. `CodexQuotaProvider` создаёт только собственный CLI-процесс, выполняет initialize / initialized / account/rateLimits/read, выбирает окна по длительности 10080 / 300 минут и закрывает процесс. Другие методы, чаты и модели не вызываются. Вывод диагностики сервера отбрасывается. В панель попадают только нормализованные проценты и даты, без аккаунтных идентификаторов и токенов.

`ClaudeQuotaProvider` в фоновом потоке читает имена кнопок `Usage:` через Windows UI Automation; действия над интерфейсом отсутствуют. Поддерживается английский индикатор общего недельного окна и пятичасового / сессионного окна, если они присутствуют. Краткое время сброса переводится из локального часового пояса; неизменившийся индикатор после сброса не переносится автоматически на следующую неделю. Отсутствие окна не заменяется нулевой загрузкой или полным остатком. Если UIA завис, удерживается одна операция без запуска следующих.

`QuotaTicker` рисует группы цветных скруглённых тегов с двойной буферизацией и шагом по монотонному времени (42 логических px/s, до 30 кадров/с). Метрики текста кэшируются до изменения значений или шрифта; GDI-ресурсы освобождаются. `QuotaText.Tags` отделяет данные представления от рендеринга и фильтрует окна через QuotaVisibility. Четыре независимых флага управляют недельным и пятичасовым окном каждого сервиса; по умолчанию Codex fiveHour выключен для сохранения прежнего вида. Один фильтр применяется к ленте, подсказке и подробностям. При отключении всех четырёх окон лента скрывается и не резервирует место. Копии разделены отступом для непрерывного цикла. Наведение приостанавливает движение. Лента занимает только свободную область слева от системных блоков; изменение её текста не влияет на их ширину. Проценты опрашиваются раз в минуту отдельно от цикла CPU/RAM, обратный отсчёт формируется из абсолютных дат. При закрытии отменяются запросы; чтение CLI ограничено 20 секундами, UIA — ожиданием до 12 секунд. Сетевое или UI-ожидание не блокирует системный опрос.

`Settings` хранит пользовательские настройки атомарно. UI проверяет диапазоны, порядок порогов и достижимость восстановления. Логи ограничены двумя файлами примерно по 128 KiB. По запросу создаётся один локальный снимок диагностики.

Шестерёнка `BarForm` открывает отдельное меню видимости: ShowLeaders, ShowQueue, ShowCpu, ShowGraph, ShowRam, ShowDiskC, ShowDiskD, существующее ShowTemperature и ShowQuotas. Флаги по умолчанию включены и сохраняются атомарно до применения раскладки. При ошибке сохранения переключатель откатывается. Выключенные блоки исключаются из ResponsiveLayout и списка автоматического переполнения. Для шестерёнки всегда оставляется место справа; лента может быть скрыта отдельно. Сохранение открытого диалога общих настроек копирует актуальные флаги, чтобы не затереть быстрые переключения, сделанные после его открытия.

Один экземпляр обеспечивается сеансовым mutex. Повторный запуск передаёт команду зарегистрированным оконным сообщением. Обычная панель не забирает фокус при обновлении. Настройки — отдельное активируемое окно. Установка self-contained; ярлыки имеют общий AppUserModelID. TaskbarManager проверяется через desktop marker interface, LAF, IsPinningAllowed и IsCurrentAppPinnedAsync. Установщик не вызывает запрос закрепления.

`Startup` регистрирует задачу Task Scheduler через COM: LogonTrigger текущего SID, Delay PT15S, InteractiveToken, LeastPrivilege, без пароля. Действие ссылается на стабильный установленный exe с `--startup`. IgnoreNew и mutex предотвращают дубли; у задачи нет ограничения времени и условий питания. RestartOnFailure: до трёх повторов через минуту. Это не watchdog при обычном выходе. Старый startup-ярлык удаляется только после успешной регистрации. Установщик сохраняет Enabled существующей задачи, поддерживает переход со старого ярлыка и явное `-EnableStartup`; деинсталлятор удаляет задачу до удаления exe.

## Ограничения и непроверенные сценарии

- Основной сценарий размещения — нижняя штатная панель Windows 11. При другом расположении системной панели AppBar всё равно резервирует нижний край выбранного монитора.
- Поддерживается одна панель на одном мониторе; собственного автоскрытия нет. Существующее автоскрытие Windows не меняется.
- Несколько processor groups не агрегируются: CPU явно недоступен при >64 логических процессорах.
- Температурный модуль поддерживает одну NVIDIA GPU из существующего драйвера. Смена GPU, CPU, AMD/Intel требуют новых провайдеров.
- Выбор температурных порогов оставлен пользователю; GPU-цвет сравнивается с ними при каждом чтении без отдельного температурного гистерезиса.
- Сон, Explorer restart, другое DPI, отключение монитора, настоящий fullscreen и ARM64 требуют дополнительных проверок на соответствующих конфигурациях.
- Подтверждение TaskbarManager и реальный запуск после нового входа в Windows не автоматизировались.
- Лимиты зависят от того, что выдаёт аккаунт / показывает индикатор Claude. Отдельные окна могут отсутствовать. Для Claude требуется открытая вкладка Code с доступным индикатором Usage; локальная UI-подпись может отражать кэш самого приложения. Много аккаунтов и произвольные языки интерфейса Claude не поддерживаются.
